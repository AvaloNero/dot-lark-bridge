# 向主线程申请的最少真实授权

先确认用户是否已有应用。有则只取得其非秘密 App ID，优先复用官方已有应用扫码更新流程，不要求重复创建。开始扫码前需明确批准更新该应用的最小权限/事件配置，并允许官方把凭据返回云电脑内存；用户核对官方权限差异后确认。私有保存、绑定及长期运行单独批准。以下范围可逐步批准；“继续实现”不是账号或费用许可。

| 范围 | 需主线程明确的内容 | 具体外部动作 |
| --- | --- | --- |
| A 飞书应用 | 指定租户及已有 App ID（或明确新建）、仅一名主人、仅两项 tenant scopes 和一项事件、仅主人可用/发布启用 | 调用官方 registerApp 的已选模式；主人核对权限差异并扫码；控制台启用机器人及长连接。权限为 `im:message.p2p_msg:readonly`、`im:message:send_as_bot`，事件 `im.message.receive_v1` |
| B 保存与绑定 | 指定私有秘密路径/secret store、准确 tenant_key 和已验证 owner open_id，允许保存 App Secret 与 p2p chat_id；允许一次应用 token/bot-info 只读探测及短期 WSS 配对 | 本地或云端私有文件写入；只接受已知主人的短期私聊口令；转移到批准的云秘密挂载。秘密不进聊天 |
| C 云端及当前 dot | 主线程选择供应商/地区/预算、单实例常驻 Node、持久卷与备份、域名/TLS、已有 OAuth 发行方及 owner sub/client 注册、当前这个 dot 的插件连接及事件订阅；确认是否推送代码 | 经批准后部署/发布 MCP、配置长期权限与秘密、连接目标 dot、订阅并进行一条真实私聊验收 |

仓库 push 也是另行授权动作，当前仅有本地提交和源码包。若主线程选安全 MCP 隧道，还需明确 Platform/ChatGPT 工作区、创建隧道权限、受限 runtime key 的保存位置；它不能代替本桥的用户认证，见 [auth-decision.md](auth-decision.md)。不请求模型 API key。

已完成代码缺口：可预览的注册/配对向导、秘密文件加载、拒绝身份冲突、脱敏本地/获准远程检查、固定提交源码打包及常驻启动模板。仍待真实验证：控制台实际权限和可用范围、官方扫码返回身份、WSS、发行方 authorization-code/PKCE 流程、目标 dot 的 MCP Events 可用性、云端磁盘与电脑离线验收。

主线程批准前可以继续本地测试、修复和打包；不得生成真实验证链接、取得或配置真实秘密、配对账号、创建付费资源或公网发布。审批需写清 A/B/C 中的具体范围，不在聊天中索要 App Secret、token、Cookie 或私有数据库。
